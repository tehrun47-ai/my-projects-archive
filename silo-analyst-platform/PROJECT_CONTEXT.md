# SILO Analyst Platform (VIP Community) — Project Context

## این پروژه چیه؟
یه پلتفرم ردیابی و امتیازدهی به تحلیل‌گرها/معامله‌گرهاست — «SILO VIP Community». هدف اینه که فعالیت تحلیل‌گرها توی یه گروه Telegram (تحلیل، ستاپ اسکالپ/سویینگ، نتایج) به‌صورت خودکار و قابل‌بازپخش ثبت بشه، تبدیل به رکورد عملکرد (Track Record) بشه، و در آینده مبنای رتبه‌بندی، بازارچه، و اعتبار داخلی (SILO Credits) بشه.

## این پروژه با «SILO Trading Journal» فرق داره!
این یه پروژه‌ی **کاملاً جدا**ست از پروژه‌ی قبلی (ژورنال معاملاتی شخصی). این یکی برای جامعه‌ی VIP و تحلیل‌گرهاست، نه ثبت معاملات شخصی. جزئیات پروژه‌ی قبلی توی پوشه‌ی `../silo-trading-journal/` هست — قاطی‌شون نکن.

## Stack فنی
- **Backend/DB:** Supabase/PostgreSQL (منبع حقیقت اصلی)
- **دریافت داده:** Cloudflare Worker (Webhook تلگرام) + Cloudflare Queue (اختیاری، برای Retry)
- **موتور Protocol:** یه بسته‌ی TypeScript خالص و جدا (`services/protocol-engine/`) — بدون وابستگی به شبکه، کاملاً قابل‌تست
- **UI آینده:** React + TypeScript (PWA، هم روی وب هم Telegram Mini App)

## پیشینه‌ی مهم پروژه (قبل از اینکه من واردش بشم)
این پروژه قبلاً یه نسخه‌ی قدیمی‌تر داشت (با Google Apps Script، اسمش داخلی «Majma» بود) که کاملاً **منجمد و بایگانی** شده (زیر `legacy/apps-script-v1/`). یه پروتکل قدیمی‌تر («Protocol v0») هم وجود داشت که **دیگه استفاده نمی‌شه** و نباید مبنای هیچ پیاده‌سازی جدیدی باشه.

استاد یه سند نهایی و قطعی به اسم **Protocol v1** نوشته (`docs/VIP_COMMUNITY_PROTOCOL_V1.md`) که قوانین دقیق و قطعی همه‌چیز رو مشخص می‌کنه — این سند هیچ ابهامی نداره، هر پیام باید دقیقاً به یکی از سه حالت برسه: `VALID`, `INVALID`, یا `IGNORED` — هیچ‌وقت یه صف «بررسی دستی» وجود نداره.

## اصل خیلی مهم: این Repository فقط مال همین پروژه‌ست
قبلاً این Repository یه نسخه‌ی اضافه از یه پروژه‌ی دیگه (Instagram Automation) هم توش بود که پاک شد. قانون سخت‌گیرانه‌ای که استاد گذاشته:
> هر محصول، Repository خودشو داره. هیچ محصولی نباید به کد یا Deploy یه محصول دیگه وابسته باشه.

پس این پروژه هیچ‌وقت نباید به Journal، Instagram Automation، یا هر پروژه‌ی دیگه‌ی استاد وابسته بشه.
