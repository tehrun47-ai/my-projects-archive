# SILO — مسیر کامل پروژه (Timeline)

## مرحله ۰: فرم اولیه
یه فرم HTML تک‌صفحه‌ای برای ثبت پیش‌از-معامله ساخته شد — تم تیره، فارسی/RTL، با Export به Excel و قابلیت نصب به‌عنوان PWA.

## مرحله ۱: معماری
استاد یه Brief خیلی مفصل فرستاد (۵۱ بند اصلی + ۲۷ بند مربوط به Monetization). نکات کلیدی:
- ژورنال باید مستقل از استراتژی خاص باشه (نه فقط برای یه روش خاص معامله)
- اصل «حداقل ورودی، حداکثر بینش استخراج‌شده» — یعنی کاربر کمترین داده رو دستی وارد کنه، بقیه خودکار محاسبه بشه
- سیستم Setup (الگوی معاملاتی) و Tag قابل‌استفاده‌ی مجدد
- دفتر کل سرمایه (Capital Ledger) به‌جای وارد کردن سرمایه برای هر معامله
- داشبورد اصلی با تحلیل‌های آماری
- موتور Nudge (هشدارهای رفتاری هوشمند)
- مدل فعال‌سازی: ۳ معامله‌ی رایگان، بعدش نیاز به کد فعال‌سازی (این بعداً کاملاً حذف شد — به بخش P0 نگاه کن)
- زیرساخت آماده برای بازارچه‌ی آینده (Module Marketplace) و اعتبار داخلی (Silo Credits) — فقط معماری، نه پیاده‌سازی

بعد از چند دور اصلاح، معماری نسخه‌ی سوم (v3) نهایی تأیید شد.

## مرحله ۲: پیاده‌سازی اولیه (Migration ۰۰۰۱ تا ۰۰۰۹)
دیتابیس کامل ساخته شد: هویت کاربر، دفتر کل سرمایه، سیستم فعال‌سازی، هسته‌ی ژورنال (معاملات، Setup، Tag)، امنیت سطح ردیف (RLS)، توابع اتمیک (بستن معامله، فعال‌سازی)، Storage برای اسکرین‌شات، موتور Nudge.

دو دور Audit امنیتی جدی توسط استاد انجام شد و همه‌ی مشکلات (مثل امکان خودارتقایی به ادمین، مسابقه‌ی داده‌ای هنگام بستن هم‌زمان چند معامله) پیدا و رفع شدن. یه باگ حیاتی هم پیدا شد: یه Policy امنیتی قدیمی که باید حذف می‌شد، هنوز فعال بود.

تست کامل روی یه PostgreSQL محلی (چون به Supabase واقعی دسترسی نبود) انجام شد — همه‌ی ۱۲ سناریو Pass شدن.

## SILO Master Prompt — تغییر بزرگ هویت
یه سند بسیار بزرگ و کامل (اسمش «SILO Master Implementation Prompt») از طرف استاد اومد که کل محصول رو با هویت جدید (SILO) و فیچرهای زیادی بازتعریف کرد. قبل از هر کاری، طبق دستور خودِ سند، یه **گزارش شکاف (Gap Audit)** کامل نوشته شد که وضعیت کد فعلی رو با سند جدید مقایسه کرد و فازبندی P0 تا P3 پیشنهاد داد.

## فاز P0 — حذف کامل دیوار فعال‌سازی
مهم‌ترین تصمیم این سند: **هسته‌ی ژورنال هرگز نباید نیاز به پرداخت یا فعال‌سازی داشته باشه.** دیوار «۳ معامله‌ی رایگان» کاملاً از تابع `close_trade` و از رابط کاربری حذف شد. زیرساخت فعال‌سازی (کدها، دعوت‌نامه‌ها) نگه داشته شد ولی دیگه به هسته وصل نیست — برای آینده (فیچرهای Premium) ذخیره شده.

## فاز P1 — تکمیل هسته
شامل چند دور بود:
- ماشین‌حساب دوطرفه‌ی ریسک/لات + Instrument Registry
- تشخیص خودکار Session معاملاتی، روز هفته، بازه‌ی زمانی — **مهم:** اولین نسخه بر اساس ساعت ثابت UTC بود که اشتباه بود (بازار در تغییر ساعت تابستانی/زمستانی جابه‌جا می‌شه ولی این محاسبه نه). با تست مستقل (مقایسه‌ی زمستون/تابستون) اصلاح شد تا واقعاً بر اساس Timezone باشه.
- برترین‌ها/دردسرها (تحلیل تک‌متغیره) با حداقل نمونه‌ی ۵ معامله برای هر رتبه‌بندی — تا هیچ‌وقت با نمونه‌ی خیلی کم، ادعای «بهترین ستاپ» نشه
- Quick Journal Templates (قالب‌های ثبت سریع، قابل انتخاب دقیق کدوم فیلد ذخیره بشه)
- نمودارهای عملکرد (منحنی سرمایه، سود/زیان تجمعی، Win Rate، Drawdown)
- مرور دوره‌ای (هفتگی/ماهانه/فصلی) با محاسبه‌ی دقیق بر اساس Timezone خودِ کاربر (نه ساعت مرورگر)

نکته‌ی جالب: اولین تلاش برای محاسبه‌ی ارزش ریسک نمادهای خاص (مثل USDJPY) فقط یه هشدار «تقریبیه» نشون می‌داد. استاد گفت این کار آسون‌ترین راهه، نه درست‌ترین — باید فرمول واقعی پیاده بشه. با فرمول استاندارد پیپ اصلاح شد و با تست مستقیم ثابت شد که واقعاً از قیمت لحظه‌ای محاسبه می‌شه.

P1 بعد از چند دور Review نهایتاً «Final Approved» اعلام شد.

## فاز P2 — تجربه‌ی کامل محصول
شامل: Export حرفه‌ای گزارش (PDF و Word، با تصاویر واقعی از چارت‌های آپلودشده، بعد از ۱۰ معامله‌ی بسته‌شده فعال می‌شه)، ویترین محتوا (Content Showcase) با اسلایدهای واقعی از اکوسیستم استاد (Live Trader New York، Trade Talk، و...)، پنل مدیریت کامل، ورودی انجمن، بخش آموزش، Milestones (دستاوردها)، Pinned Insights (سنجاق‌کردن بینش‌ها)، سیستم تم (تاریک/روشن/سیستم)، و طراحی واقعاً Responsive (نه فقط عریض‌ترشدن، بلکه ساختار متفاوت موبایل در مقابل دسکتاپ — نوار پایین در مقابل Sidebar).

بعد از دو دور Review دقیق (که هرکدوم چندتا مشکل واقعی UX/معماری پیدا کردن، مثل Token های رنگ که فقط توی حالت تاریک تعریف شده بودن)، PR نهایی P2 تأیید و Merge شد.

## گذار به Workflow کاملاً GitHub-محور
از یه‌جایی به بعد، کل فرآیند کار تغییر کرد: به‌جای فایل Zip رفت‌وبرگشت توی چت، مستقیم به Repository استاد (خصوصی) روی GitHub وصل شدیم — با Personal Access Token که من (مصطفی) می‌سازم. از اون به بعد:
- استاد یه GitHub Issue می‌سازه با مشخصات دقیق کار
- Claude از روی آخرین `main`، یه Branch جدا می‌سازه
- فقط همون کار مشخص‌شده رو انجام می‌ده، تست می‌گیره، Pull Request باز می‌کنه
- Merge و Review نهایی همیشه دست خودِ استاده، نه Claude

## Issue‌های حل‌شده بعد از P2
- **Issue #2 — Security Hardening (Migration 0026):** گزارش Supabase Security Advisor نشون داد ۸ تا تابع دیتابیس `search_path` امن نداشتن، و ۹ تا RPC حساس حتی برای کاربرهای وارد‌نشده (anon) هم قابل‌اجرا بودن. یه نکته‌ی فنی جالب: اولین تلاش برای قطع دسترسی `anon` عملاً کار نمی‌کرد، چون `anon` از **دو مسیر جدا** دسترسی داشت (هم از پیش‌فرض خودِ PostgreSQL، هم از پیش‌فرض خودِ Supabase) — تست‌های خودمون همین رو گرفتن و اصلاح شد.
- **Issue #4 — باگ Onboarding:** بعد از ثبت‌نام اولیه، گاهی دکمه‌ی «در حال ثبت...» گیر می‌کرد، یا بعد از Refresh صفحه، کاربر (با اینکه ثبت‌نامش کامل بود) دوباره به صفحه‌ی Onboarding می‌رفت. علتش ۳ باگ جدا بود که با هم دیده می‌شدن؛ مهم‌ترینش این بود که یه خطای بارگذاری Profile، بی‌صدا و بدون هیچ پیامی، شبیه «کاربر تازه‌واردی» رفتار می‌کرد. با یه لایه‌ی تصمیم‌گیری Pure و قابل‌تست، این مشکل کاملاً رفع شد.
