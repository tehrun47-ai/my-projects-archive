# پرامپت آماده برای شروع با یه AI جدید

اگه می‌خوای Claude (یا هر AI دیگه‌ای) رو در جریان کامل این پروژه بذاری، این متن رو کپی کن و اول از همه بهش بده:

---

من (مصطفی) دارم یه پروژه‌ی واقعی به اسم **SILO** (یه ژورنال معاملاتی هوشمند) رو برای استادم (سینا ابراهیمی، یه مدرس معامله‌گری) می‌سازم. این پروژه از قبل هفته‌ها روش کار شده و توی این آرشیو، تاریخچه‌ی کاملش هست:

- `PROJECT_CONTEXT.md` — این پروژه چیه، Stack فنی‌ش چیه، نقش من چیه
- `TIMELINE.md` — کل مسیر پروژه از شروع تا الان
- `DECISIONS.md` — تصمیم‌های مهم و چرایی‌شون (این‌ها رو زیر پا نذار)
- `BUGS-AND-LEARNINGS.md` — باگ‌های واقعی که پیدا و رفع شده (تا دوباره تکرار نشن)
- `CURRENT-STATUS.md` — دقیقاً الان کجاییم و Workflow فعلی چیه

لطفاً همه‌ی این فایل‌ها رو بخون (به همین ترتیب)، بعد بگو آماده‌ای برای ادامه‌ی کار یا سؤالی داری.

**نکات حیاتی که باید بدونی:**
1. کد واقعی این پروژه توی یه Repository جداست (نه اینجا): `github.com/sina-ebrahimi-l/silo-trading-journal-app` — Private، و من به‌عنوان Collaborator (`tehrun47-ai`) بهش دسترسی دارم
2. کل Workflow پروژه از طریق GitHub Issue/PR انجام می‌شه — استاد Issue می‌سازه، AI روی یه Branch جدا کار می‌کنه، تست می‌گیره، PR باز می‌کنه، متوقف می‌شه تا Review
3. هیچ‌وقت مستقیم روی Branch اصلی (`main`) کار نکن
4. هیچ‌وقت خودت PR رو Merge نکن
5. هیچ‌وقت بیشتر از چیزی که توی Issue خواسته شده، تغییر نده — حتی اگه یه چیز دیگه هم به‌نظرت نیاز به اصلاح داره
6. برای دسترسی به Repository، من یه GitHub Personal Access Token می‌سازم و بهت می‌دم — بعد از استفاده، اگه پروژه هنوز ادامه داره، بهم نگو پاکش کنم (این اشتباه قبلی بود که باعث دوباره‌کاری شد)

---

## اگه می‌خوای فقط یه بخش خاص رو ادامه بدی
اگه یه کار مشخص مونده (مثلاً یه PR خاص که هنوز Review نشده)، بعد از دادن پرامپت بالا، این‌رو هم اضافه کن:
> «الان دقیقاً منتظر [X] هستیم — لطفاً وضعیت [لینک PR/Issue] رو چک کن و ببین چیکار لازمه.»
