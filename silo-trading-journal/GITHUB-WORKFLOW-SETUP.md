# SILO — راهنمای عملی اتصال به GitHub (طبق تجربه‌ی واقعی)

این فایل خلاصه‌ی عملی همون کاریه که واقعاً برای وصل‌کردن Claude به Repository استاد لازم شد — تا دفعه‌ی بعد سریع‌تر انجام بشه.

## قدم ۱: ساخت حساب گیت‌هاب (اگه نداری)
`github.com` → Sign up → یه Username انتخاب کن (همیشه همون رو نگه دار، مثل `tehrun47-ai`)

## قدم ۲: گرفتن دسترسی Collaborator
Username خودت رو به استاد بده، ازش بخواه:
> Repository → Settings → Collaborators and teams → Add people → همون Username رو اضافه کنه

یه ایمیل دعوت میاد، قبولش کن.

## قدم ۳: ساخت Personal Access Token
`github.com` → عکس پروفایل → Settings → پایین صفحه: Developer settings → Personal access tokens → **Tokens (classic)** (نه Fine-grained — چون Fine-grained فقط Repositoryهایی که خودت مالکشی رو نشون می‌ده، نه Repository استاد)

- Generate new token (classic)
- اسم دلخواه
- **Expiration: حداقل ۳۰ روز** (نه کوتاه — چون این پروژه چند دور کار داره)
- Scope: تیک بزن روی **`repo`** و **`workflow`** (هردو از همون اول، تا نیاز به ساخت دوباره نباشه)
- Generate token
- کدی که می‌ده (با `ghp_` شروع می‌شه) رو کپی کن و به Claude بده

## نکته‌ی خیلی مهم: تا آخر پروژه، توکن رو پاک نکن
یه اشتباه که قبلاً افتاد: بعد از هر کار، توکن پاک می‌شد، و برای کار بعدی باید از اول ساخته می‌شد. **این‌کارو نکن.** با Expiration ۳۰ روزه، توکن رو نگه دار و هر بار که Claude نیاز داشت، همون رو بده. فقط در پایان کامل پروژه (یا اگه یه‌جا احساس کردی امنیتش به خطر افتاده) پاکش کن.

## اگه پیغام "Bad credentials" گرفتی
یعنی توکن منقضی شده یا پاک شده — باید یه توکن جدید بسازی (دقیقاً طبق قدم ۳).

## در مورد Vercel/Supabase
طبق تصمیم نهایی استاد، **هیچ‌وقت لازم نیست** به این دوتا دسترسی بدی. Deploy (روی Vercel) خودکار بعد از هر Merge روی main اتفاق می‌افته، و QA/بررسی محیط زنده کاملاً دست خودِ استاده.
