# پرامپت شروع — پروژه‌ی سوم (جزئیات هنوز نامشخص، احتمالاً یه وبسایت)

این متن رو کپی کن و اول از همه، توی یه چت **جدید و جدا** بفرست:

---

من (مصطفی) دارم یه پروژه‌ی جدید و جدا برای همون استادم (سینا ابراهیمی) شروع می‌کنم — احتمالاً یه وبسایته، ولی جزئیات دقیقش رو هنوز ندارم و به‌زودی ازش می‌گیرم.

این پروژه کاملاً جدا از دو پروژه‌ی دیگه‌ای هست که قبلاً باهاش کار کردیم:
1. **SILO Trading Journal** — یه ژورنال معاملاتی (Repository: `github.com/sina-ebrahimi-l/silo-trading-journal-app`)
2. **SILO Analyst Platform** — یه پلتفرم ردیابی تحلیل‌گرها روی Telegram (Repository: `github.com/sina-ebrahimi-l/silo-analyst-platform`)

**قوانین ثابتی که توی هر دو پروژه‌ی قبلی جواب داد و باید همینجا هم رعایت بشه:**

1. **هر پروژه، Repository خودشو داره** — این پروژه‌ی جدید نباید به کد یا Deploy پروژه‌های قبلی وابسته باشه
2. وقتی Repository واقعی این پروژه مشخص شد، **قبل از هر تغییری**، اول باید فایل‌های راهنمای خودِ Repository (مثل `README.md`, `AGENTS.md` یا `DEV_AGENT.md`, و هر سند دیگه‌ای که استاد لینک بده) رو کامل بخونی — نه فرض کنی، نه از حافظه بسازی
3. **مستقیم روی Branch اصلی (`main`) کار نکن** — همیشه یه Branch جدا برای هر کار بساز
4. **خودت هیچ‌وقت PR رو Merge نکن** — فقط باز کن، تست بده، و متوقف شو تا استاد Review کنه
5. **فقط دقیقاً همون کاری که خواسته شده رو انجام بده** — حتی اگه یه چیز دیگه هم به‌نظرت نیاز به اصلاح داره، بدون اجازه‌ی جدید دست نزن
6. برای دسترسی به Repository، یه GitHub Personal Access Token لازمه — من می‌سازم (نوع Classic، دسترسی `repo` + `workflow`، Expiration حداقل ۳۰ روز) و بهت می‌دم. **این Token رو زود پاک نکن** — تا آخر پروژه نگهش می‌دارم
7. هر تغییر دیتابیس (اگه پروژه دیتابیس داشته باشه)، همیشه یه Migration جدید و شماره‌دار — هیچ‌وقت Migration قدیمی رو ویرایش نکن
8. بعد از هر کار، حتماً تست کامل بگیر (چه رگرسیون، چه تست واحد) و نتیجه رو دقیق گزارش بده — هیچ‌وقت ادعا نکن کاری «تمومه» بدون تست واقعی

**کاری که الان لازم دارم ازت:**
فعلاً هیچ‌کاری شروع نکن. فقط این پیام رو تأیید کن که خوندی و فهمیدی، و منتظر بمون تا جزئیات واقعی پروژه (اسم، Repository، بریف کار) رو برات بفرستم.

---

## بعد از اینکه جزئیات واقعی رو از استاد گرفتی
وقتی استاد Repository و بریف واقعی رو داد، اون‌موقع می‌تونی به همون چت جدید بگی دقیقاً همون‌جوری که با دو پروژه‌ی قبلی جلو رفتیم (خوندن مستندات → Branch جدا → کار → تست → PR → توقف) جلو بره.

اگه خواستی، بعد از شروع واقعی کار، بگو تا برای همین پروژه هم یه پوشه‌ی آرشیو (مثل دوتای قبلی) توی `my-projects-archive` بسازم.
